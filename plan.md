# Plan to Fix Benchmark Tests

The primary objective is to get the `GroundTruthAnswerGenerator` to pass the validation suite with a 100% success rate. The core of the problem is a recurring `NameError` in the dynamically generated test files, which indicates that the test context (imports, helper functions) is being lost.

Here is the step-by-step plan to fix this:

1.  **Stabilize the Test Runner**:
    *   The `PytestBenchmarkRunner` is the source of the instability. I will implement a robust, regex-based code injection method (`_inject_code`) that preserves the entire original test file's content while replacing only the code between the `# BEGIN: CODE` and `# END: CODE` markers. This will ensure that all necessary context is available to the test.

2.  **Correct the Answer Generator**:
    *   The `GroundTruthAnswerGenerator` must be updated to work with the new runner. Its `_extract_code_snippet` method will be modified to extract *only* the agent definition from between the `BEGIN/END` markers in the ground truth files.

3.  **Synchronize Signatures**:
    *   I will ensure the `generate_answer` method signature is consistent across the `AnswerGenerator` base class and all its implementations, returning a `tuple[GeneratedAnswer, str]` to avoid the "not enough values to unpack" error.

4.  **Fix Data Integrity Issues**:
    *   I will review and correct the ground truth files that have been identified as problematic:
        *   `test_20_expanded_callbacks.py`: Ensure the file is structured correctly for the new runner logic, with helpers outside the `BEGIN/END` block.
        *   `test_06_loop_agent.py`: Correct the agent's instruction to ensure the test assertion can pass.

5.  **Final Validation**:
    *   Once all components are corrected and aligned, I will execute the validation suite (`env/bin/pytest benchmarks/test_benchmarks.py`) to confirm that the `GroundTruthAnswerGenerator` achieves a 100% pass rate.

## Verification Steps

After each major change, I will perform the following verification steps:

1.  **Static Analysis**: Run `./autoformat.sh` to ensure code formatting and style conventions are maintained.
2.  **Unit Test Execution**: Run the primary validation suite using the command `env/bin/pytest benchmarks/test_benchmarks.py`.
3.  **Analyze Output**:
    *   **Success Condition**: The test suite completes successfully with the `GroundTruthAnswerGenerator` achieving a 100% pass rate.
    *   **Failure Analysis**: If the tests fail, I will carefully examine the `pytest` output, including the stack trace and the captured stdout/stderr for the failing test case. This will involve:
        *   Identifying the specific benchmark that failed (e.g., `test_20_expanded_callbacks.py`).
        *   Noting the type of error (`NameError`, `AssertionError`, etc.).
        *   Inspecting the temporary test file generated by the `PytestBenchmarkRunner` to understand the context of the failure.
4.  **Iterate**: I will repeat these verification steps after each attempted fix until the success condition is met.
